# Foundation research

Research date: **2026-11-03**. Decision: compose a small application from independent libraries. Treat this as a bounded source review, not an independent security certification. Source trees, dependency manifests, selected implementations, tests and workflows were inspected through GitHub's API; the upstream suites were **not executed** here. The Komanook checks and measurements are recorded separately.

## Recommendation

Use Go's HTTP server, templ, PostgreSQL, sqlc/pgx, mature session/CSRF primitives, narrowly scoped Datastar enhancement and MannerHTML. Own a few application components and the reader. This keeps deployment to the application plus PostgreSQL, while leaving image storage and a worker as explicit boundaries. No candidate supplies Komanook's rights model, manga reader, publication lifecycle or upload processing safely out of the box.

The decision is about fit and maintenance cost. It is **not** a claim that composing these libraries is faster than the frameworks: no comparative application benchmark was performed. Revisit Datapages if long-lived collaborative views become a real requirement; revisit a generator if its generated product scope closely matches a future application.

## goilerplate: credible generator, wrong product breadth

An important discrepancy: the fetched [website](https://goilerplate.com/) still described a paid v3 product, but the inspected [v4 README](https://github.com/axadrn/goilerplate/blob/69ea66d767da9bea09e56f87a2333d679a4e8c20/README.md) and source describe a free, local generator. The CLI is MIT and the template is explicitly [0BSD](https://github.com/axadrn/goilerplate/blob/69ea66d767da9bea09e56f87a2333d679a4e8c20/LICENSE-0BSD). The paid product terms shown by the website should not be projected onto this source snapshot.

The actual [template manifest](https://github.com/axadrn/goilerplate/blob/69ea66d767da9bea09e56f87a2333d679a4e8c20/generator/_template/go.mod.tmpl) selects templ, shadcn-templ sources, Datastar Go SDK, PostgreSQL or SQLite, goose, SMTP or Resend, Sentry, and optional S3/OAuth/workspaces/API code. It uses sqlx rather than sqlc, and the generator's payment choice is Stripe or Polar rather than an absent billing module. The [generator selector](https://github.com/axadrn/goilerplate/blob/69ea66d767da9bea09e56f87a2333d679a4e8c20/generator/README.md) removes unselected files; this is demonstrable selection logic, not merely a feature list.

Security is substantial application code, not an external identity system. The [auth service](https://github.com/axadrn/goilerplate/blob/69ea66d767da9bea09e56f87a2333d679a4e8c20/generator/_template/internal/service/auth.no_workspaces.go.tmpl) uses bcrypt, cryptographic random tokens, hashed database sessions and replacement/revocation flows. [CSRF middleware](https://github.com/axadrn/goilerplate/blob/69ea66d767da9bea09e56f87a2333d679a4e8c20/generator/_template/internal/middleware/csrf.go.tmpl) and corresponding tests exist. This still requires an application-specific audit; importing the generator does not remove responsibility for account recovery, authorization or proxy trust.

Storage is not a chapter pipeline: [FileService.Upload](https://github.com/axadrn/goilerplate/blob/69ea66d767da9bea09e56f87a2333d679a4e8c20/generator/_template/internal/service/file.storage.go) explicitly delegates validation to callers, saves the object before inserting its record, then attempts compensation on database failure. Its private URL method falls back to a public URL when signing fails. That behavior must be reviewed against bucket policy before reuse for private content. It does not demonstrate bounded decompression, image re-encoding, rights checks or atomic chapter publication.

The [CI workflow](https://github.com/axadrn/goilerplate/blob/69ea66d767da9bea09e56f87a2333d679a4e8c20/.github/workflows/ci.yml) includes generated-configuration matrices, regeneration checks, vet, build and race tests. Deployment and email integrations are useful reference material. **Reject wholesale adoption**: removing billing/admin/tenant assumptions and replacing data access would cost more than a focused composition. Keep its practices of versioned assets, explicit generation, configuration validation and generated-code drift checks.

## go-starter: close stack, material security gaps

The [manifest](https://github.com/milzamsz/go-starter/blob/51956467437e4d9db921c38741dabbd980985558/go.mod) demonstrates chi, pgx, sqlc outputs, goose, validator, bcrypt, JWT/OAuth/TOTP, Casbin, Datastar, templui, Asynq and Redis. This is a real full-stack implementation with [transaction helpers](https://github.com/milzamsz/go-starter/blob/51956467437e4d9db921c38741dabbd980985558/internal/database/database.go), worker tasks and an SMTP sender. Redis is an additional operational dependency; Stripe and generic role machinery exceed this slice.

The [README](https://github.com/milzamsz/go-starter/blob/51956467437e4d9db921c38741dabbd980985558/README.md) claims server-side session cookies. In the inspected path, [login places the JWT access token in a cookie and logout only clears that cookie](https://github.com/milzamsz/go-starter/blob/51956467437e4d9db921c38741dabbd980985558/internal/auth/handlers_api.go). [AuthContext](https://github.com/milzamsz/go-starter/blob/51956467437e4d9db921c38741dabbd980985558/internal/middleware/auth.go) verifies a JWT and refreshes user role data, but does not check a server-side session record. Thus the inspected logout path does not revoke a copied token. A sessions schema alone is not proof of revocation.

The hand-written [CSRF middleware](https://github.com/milzamsz/go-starter/blob/51956467437e4d9db921c38741dabbd980985558/internal/middleware/csrf.go) skips all `/api/` requests, including the cookie-issuing auth surface, compares an unsigned cookie token, and substitutes a constant if randomness fails. These are concrete reasons to avoid copying that implementation. They are source-review observations, not a claim that every deployment is remotely exploitable. The [auth service](https://github.com/milzamsz/go-starter/blob/51956467437e4d9db921c38741dabbd980985558/internal/auth/service.go) also performs multi-step verification/reset changes without the transaction helper and ignores selected enqueue/update failures.

Its [local storage implementation](https://github.com/milzamsz/go-starter/blob/51956467437e4d9db921c38741dabbd980985558/internal/storage/storage.go) copies arbitrary readers to disk and ignores content type. This is a storage adapter, not secure upload validation. [CI](https://github.com/milzamsz/go-starter/blob/51956467437e4d9db921c38741dabbd980985558/.github/workflows/ci.yml) includes generation/race/build checks, but installs floating `@latest` tools. Only a small number of Go test files were present, and no browser coverage was found in the tree. **Reject as a security foundation**; retain its conventional SQL/query/handler separation as a useful example.

## Datapages: useful framework, unnecessary runtime model today

The [README](https://github.com/romshark/datapages/blob/4909ec11f505d756f27a132e2e904c3fac5dd603/README.md) describes a beta whose APIs can still change. The source [manifest](https://github.com/romshark/datapages/blob/4909ec11f505d756f27a132e2e904c3fac5dd603/go.mod) requires Go 1.27.3 and includes a substantial generator/development toolchain. Generated routing, typed URL/actions, per-tab state, streams and broker integration are compelling for collaboration. Komanook's public catalog and independent reader do not currently need those capabilities.

The [session interfaces](https://github.com/romshark/datapages/blob/4909ec11f505d756f27a132e2e904c3fac5dd603/modules/sessions/sessions.go) are replaceable and distinguish missing sessions from backend failure. Built-in stores are memory and NATS KV, so PostgreSQL persistence requires an adapter. The [deployment guide](https://github.com/romshark/datapages/blob/4909ec11f505d756f27a132e2e904c3fac5dd603/guide/deployment.md) confirms the default scaffold expects NATS. NATS is not an unavoidable framework dependency: a different store/broker can be wired, at the cost of application integration work.

The [security guide](https://github.com/romshark/datapages/blob/4909ec11f505d756f27a132e2e904c3fac5dd603/guide/security.md) is unusually explicit about boundaries. Signed-in mutating actions receive masked session-bound CSRF checks, but actions must request and validate a session to reject expired/revoked identities. Plain signed-in form submissions lack its Datastar token header and receive 403. Authorization, custom request body limits, abuse control, TLS and untrusted expression handling remain application responsibilities. The [runtime implementation](https://github.com/romshark/datapages/blob/4909ec11f505d756f27a132e2e904c3fac5dd603/runtime/auth/auth.go) installs its token into Datastar requests by wrapping global `fetch`. These conventions deserve conscious adoption, especially where native forms are a requirement.

Source includes CSRF/session acceptance tests, fault-injection fixtures and asset caching code. The [asset guide](https://github.com/romshark/datapages/blob/4909ec11f505d756f27a132e2e904c3fac5dd603/guide/assets.md) documents ETags and optional immutable caching. Framework tests do not establish reader image performance, upload safety, migrations, transactional email or business authorization. **Defer adoption**: its generated application model and store/broker integration increase the surface we must understand. Use Datastar directly for bounded HTML updates.

## shadcn-templ: adopt selectively as owned source

This is a code-distribution system, not a security or application framework. The [README](https://github.com/axadrn/shadcn-templ/blob/b7074c1dc2cb669e916b3a51ddf8152eba356fa9/README.md) explicitly encourages building an owned component library. The [manifest](https://github.com/axadrn/shadcn-templ/blob/b7074c1dc2cb669e916b3a51ddf8152eba356fa9/go.mod) uses Go 1.26, templ 0.3.1100, tailwind-merge-go and esbuild. Preserve its [MIT notice](https://github.com/axadrn/shadcn-templ/blob/b7074c1dc2cb669e916b3a51ddf8152eba356fa9/LICENSE) when copying source.

The inspected [button template](https://github.com/axadrn/shadcn-templ/blob/b7074c1dc2cb669e916b3a51ddf8152eba356fa9/components/button/button.templ) has typed variants/sizes and native button rendering. Its link branch uses `templ.SafeURL` and `role="button"`; application navigation should keep native link semantics and URLs under application control. The current source uses `cn-*` classes whose look comes from style CSS. Copying a template without its relevant styling contract is incomplete integration.

Interactive components are controllers. [Tabs JavaScript](https://github.com/axadrn/shadcn-templ/blob/b7074c1dc2cb669e916b3a51ddf8152eba356fa9/components/tabs/tabs.js) owns selection, panel visibility, focus and attributes. Its [lifecycle runtime](https://github.com/axadrn/shadcn-templ/blob/b7074c1dc2cb669e916b3a51ddf8152eba356fa9/components/baseui/lifecycle.js) observes document mutations and initializes/destroys matching elements; an already-initialized root is not necessarily reconstructed when only its internals morph. Do not combine those tabs/dialog controllers with MannerHTML on the same widget.

**Adopt the approach and a small audited primitive subset**, with Komanook tokens, native form controls and semantic HTML. Keep provenance for copied code. Do not ship the whole runtime merely for buttons, badges and fields. Do not assume an upstream accessibility claim proves the assembled application accessible; test actual keyboard/focus behavior after patches.

## MannerHTML: narrow, appropriate progressive behavior

The [package manifest](https://github.com/samanshaiza004/mannerhtml/blob/f53713cae66e4811d0de606d769a523a4762df1b/package.json) identifies v0.3.0, MIT and no runtime dependencies. The [entry point](https://github.com/samanshaiza004/mannerhtml/blob/f53713cae66e4811d0de606d769a523a4762df1b/src/index.ts) exports/registers tabs, form and carousel elements. It enhances light DOM; it does not render templates or apply styling.

The [tabs implementation](https://github.com/samanshaiza004/mannerhtml/blob/f53713cae66e4811d0de606d769a523a4762df1b/src/tabs.ts) supports progressive anchor tabs, roving focus, arrows/Home/End, automatic/manual activation and reconnect cleanup. All panels can remain visible before upgrade. It owns `hidden`, ARIA, roles and tab stops. Structural mutations require explicit `refresh()`; it deliberately does not reconcile them automatically. Keep its root outside Datastar patch targets, or replace the whole widget deliberately with focus restoration. Do not morph half its internal model.

The [testing record](https://github.com/samanshaiza004/mannerhtml/blob/f53713cae66e4811d0de606d769a523a4762df1b/TESTING.md) reports 165 Playwright/axe checks across Chromium, Firefox and WebKit and selected manual desktop AT verification. This was not rerun here. Mobile VoiceOver/TalkBack is explicitly unverified. **Adopt one small interaction** and test our integration; avoid turning its carousel into the reader because its contract omits swipe, zoom, virtual image loading and manga pagination.

## templ-components and simpler styling

[templ-components](https://github.com/LarsArtmann/templ-components/blob/b8a4bb1a47dba50ccd05d2b795ed6b38718e97c2/README.md) offers typed Go-module components, native HTML where possible, themes, htmx/Datastar adapters, golden tests and a visual harness. Actual [tabs source](https://github.com/LarsArtmann/templ-components/blob/b8a4bb1a47dba50ccd05d2b795ed6b38718e97c2/display/tabs.templ) demonstrates both server-wired and client-side behavior. It would add another owner for focus and tab selection if combined carelessly. The [manifest](https://github.com/LarsArtmann/templ-components/blob/b8a4bb1a47dba50ccd05d2b795ed6b38718e97c2/go.mod) requires Go 1.27 and coordinates several submodules. Its [CI](https://github.com/LarsArtmann/templ-components/blob/b8a4bb1a47dba50ccd05d2b795ed6b38718e97c2/.github/workflows/ci.yaml) shows serious regression tooling, but that tooling and broad component/transport API exceed this product's needs. **Reject a second full component system**, not its useful native-HTML ideas.

| Styling choice | Practical fit |
| --- | --- |
| Owned CSS with custom properties, grid, logical properties and native controls | Smallest runtime and clearest ownership; team owns consistency and accessibility. Strong option for the reader. |
| Tailwind v4 + a few owned templ primitives | Good application ergonomics and explicit token mapping; build dependency, no browser styling runtime. Selected direction. The [official CLI](https://tailwindcss.com/docs/installation/tailwind-cli) supports compiled CSS and a standalone executable. |
| daisyUI | CSS component classes integrate with Tailwind through [a plugin](https://daisyui.com/docs/install/); useful CSS-first alternative, but adopting its themes alongside shadcn tokens creates a second design vocabulary. Not selected. |
| Pico CSS | Straightforward semantic/classless styling and MIT code, but the [maintainer says v2.1.1 is final and repositories are archived](https://picocss.com/docs/maintenance). Not selected for a new long-lived foundation. |

## Integration and security consequences

- **Do not invent session or CSRF protocols.** [SCS](https://github.com/alexedwards/scs/blob/master/README.md) supplies stable server-side session management, renewal and idle/absolute timeouts; its [pgxstore](https://github.com/alexedwards/scs/blob/master/pgxstore/pgxstore.go) supports pgx/v5 and context-aware PostgreSQL operations. [gorilla/csrf](https://github.com/gorilla/csrf/blob/main/README.md) is a maintained token-based middleware option. Go's [CrossOriginProtection](https://pkg.go.dev/net/http#CrossOriginProtection) is another established primitive for browser-origin checks. Select and test the policy in application wiring; SameSite alone is not a complete design.
- **Keep authorization in handlers/services/SQL scope.** Neither a hidden button nor a successful session validates record ownership, publication rights or upload permission. Reload current identity/permissions from the database for privileged actions. Fail closed on database errors.
- **Keep Datastar narrow.** [v1.0.4](https://github.com/starfederation/datastar/releases/tag/v1.0.4) is the observed stable runtime. [Official guidance](https://data-star.dev/guide/getting_started) recommends self-hosting. Pin and hash the local asset, retain its license, and use matching SDK/event contracts. A short action response needs no permanent SSE connection. Native forms remain the fallback.
- **Treat expressions as code.** [Datastar security documentation](https://data-star.dev/reference/security) confirms expressions execute JavaScript. Use static expressions and serialize values; HTML escaping alone does not safely construct a JavaScript expression. Its nonce CSP mode avoids requiring `unsafe-eval`, but does not sanitize expressions. `data-ignore` prevents attribute processing; `data-ignore-morph` prevents morphing, so these serve different purposes.
- **Use patched generators.** goilerplate's [changelog](https://github.com/axadrn/goilerplate/blob/69ea66d767da9bea09e56f87a2333d679a4e8c20/CHANGELOG.md) records a templ 0.3.1100 spread-attribute/URL sanitization fix. Pin the runtime and matching generator, regenerate source, and run vulnerability scanning rather than inheriting an older starter pin.
- **Use durable jobs, not request goroutines.** None of these UI tools gives Komanook atomic chapter publication. A PostgreSQL-backed queue keeps job insertion and metadata changes in one transaction, avoids a Redis/NATS service initially, and needs retries, idempotency, bounded image decoding and dead-job visibility. Select a maintained queue before public upload scale; do not build a generic job framework.
- **Keep email and uploads outside the first reader's critical path.** Add a transactional outbox/maintained queue and a real SMTP/API mailer before registration/recovery. For uploads, authorize before accepting bytes, quarantine originals, validate decoded format/dimensions/pixel count, re-encode derivatives, strip metadata and publish only after all pages succeed. R2 storage does not provide these policies.

## Dependency scan follow-up

The final pinned toolchain is Go 1.27.3. The initial scan on 1.27.2 identified the standard-library `crypto/x509` issue GO-2026-6809; the [1.27.3 release notes](https://go.dev/doc/devel/release#go1.27.3) list the certificate-verification security fixes. A later scan found GO-2026-5932 at module level in `golang.org/x/crypto@v0.58.0`, specifically its deprecated `openpgp` package. Komanook imports bcrypt from this module and does not import OpenPGP. To remove the dormant package from the dependency archive too, the pin is `v0.58.1-0.20261009181718-2f1f834330b2`, the revision the [Go vulnerability database marks fixed](https://pkg.go.dev/vuln/GO-2026-5932). Final `govulncheck` reports no vulnerabilities; `npm audit` reports zero for the locked browser/build dependencies. These are point-in-time scans, not a guarantee against future advisories.

## What remains unproven

This review does not establish comparative throughput, memory use, accessibility conformance, independent security audit results, or an upstream long-term support guarantee. Repository tests and documentation claims have been identified as such. Production launch additionally needs rights agreements, restore-tested backups, a supported deployment environment, abuse controls, operational alerting, dependency updates, and a tested incident/revocation procedure. Those are release work, not features supplied by selecting a starter.
